\section{Literature Review}
The literature review examines existing research on each game-playing AI approach to understand their general strengths and limitations. This evaluation helps to anticipate potential challenges before implementing the agents. The literature review then considers a more complex hybrid approach that demonstrates how different AI approaches can work together to build a potentially stronger agent. Finally, existing Azul implementations are reviewed to identify limitations in previous work and establish the research gap that this project intends on filling. 

\subsection{Minimax}
Yannakakis and Togelius' \emph{Artificial Intelligence and Games} describes Minimax as an algorithm for two-player adversarial games \cite{yannakakis2025artificial}. Minimax considers the possible moves available to each player in turn while assuming that both players play optimally. In a finite, deterministic, two-player, zero-sum game with perfect information, an optimal move can be found by exploring the entire game tree. However, searching the entire game tree quickly becomes infeasible as the complexity of the game increases due to the branching factor and search depth. \\

Shannon's \emph{Programming a Computer for Playing Chess} takes this idea further by considering the application of Minimax to chess \cite{shannonminimaxchess}. Since exploring the entire game tree is infeasible, Shannon proposes searching only a certain number of moves ahead and using an evaluation function to estimate the quality of the resulting game states. Shannon also considers selective search, which prioritises moves that appear more promising and hence reduce the game tree that needs to be explored. However, this comes with a risk of excluding an important alternative move. Knuth and Moore's \emph{An Analysis of Alpha-Beta Pruning} examines a further improvement that reduces the number of branches searched by excluding those that cannot influence the final Minimax decision \cite{knuthalphabeta}. However, the effectiveness of alpha-beta pruning relies on the order in which moves are considered. \\

Campbell, Hoane and Hsu's \emph{Deep Blue} demonstrates how search-based AI was developed into a chess playing system capable of playing chess at world-championship level \cite{deepblue}. It defeated the reigning World Chess Champion Garry Kasparov in 1997. Deep Blue extended Minimax with alpha-beta pruning through parallel processing, a more complex evaluation function and a grandmaster game database. Although an equivalent database is less likely to be available for Azul, the other improvements may help address the inefficiencies of basic Minimax when developing an Azul agent. Collectively, these sources can therefore inform the implementation of Minimax as a search-based baseline for comparison with the other Azul agents. However, the implementation must also determine how to represent Azul's random factory replenishment since standard Minimax assumes deterministic transitions.


\subsection{Monte Carlo Tree Search}
Browne et al.'s \emph{A Survey of Monte Carlo Tree Search Methods} describes MCTS as an iterative algorithm that involves selection, expansion, simulation and backpropagation \cite{mctshistory}. Initially, a game state is selected from the existing game tree based on a tree policy. If the selected state has an unexplored move, then that move is added to the game tree, leading to expansion of the game tree. A game is simulated from the game state using either random or some policy-guided actions. The result of the simulated game is backpropagated through the game tree. This process is repeated many times in order to allow MCTS to estimate the most promising moves using the results of simulated games. Kocsis and Szepesvári's \emph{Bandit Based Monte-Carlo Planning} introduces Upper Confidence Bounds applied to Trees (UCT) as a tree policy for guiding MCTS \cite{mctsutc}. UCT works by balancing exploitation against exploration. Exploitation revisits previously visited promising states while exploration gives more attention to unvisited or less frequently visited states. \\

Browne et al. describe MCTS as an anytime algorithm since it can return a result whenever its computation is halted, although the reliability of its results generally improves with additional computation time \cite{mctshistory}. Basic MCTS requires little domain-specific knowledge and can be effective in games where non-terminal states are difficult to evaluate, although incorporating additional knowledge can improve its performance. This is particularly relevant to Azul since an established heuristic evaluation function has not been identified which makes it difficult to estimate the values of non-terminal states reliably. However, a large branching factor or computationally expensive game simulations restrict the number of simulations that can be completed within a fixed amount of time, reducing the coverage of the game tree and producing less reliable results. These sources can therefore inform the implementation of MCTS as the baseline for the simulation-based search approach. The implementation must determine how to represent Azul's random factory replenishment during simulations. 


\subsection{Reinforcement Learning}
Yannakakis and Togelius' \emph{Artificial and Games} describes Reinforcement Learning (RL) as an approach where an agent learns by acting within an environment and receiving positive or negative rewards \cite{yannakakis2025artificial}. The agent attempts to learn a policy, which is a strategy for selecting actions that maximises the expected cumulative reward, by repeated interactions with the environment. Unlike Minimax and MCTS, RL generally requires a separate training period in which the agent explores actions and improves its policy. Much of the computational cost is hence incurred before play, potentially allowing actions to be selected quicker once training is complete. This section considers three RL approaches, namely Tabular Q-Learning, Deep Q-Networks and Proximal Policy Optimisation, before investigating self-play as a method of generating training experience in two-player games.

\subsubsection{Tabular Q-Learning}
Watkins and Dayan introduce Q-learning as an approach that incrementally updates estimates of the quality of taking each action from each state \cite{qlearning}. They prove that these estimates converge to the optimal action values under specific conditions such as repeatedly sampling every state-action pair and a discrete representation. Sutton and Barto's \emph{Reinforcement Learning: An Introduction} explains that in TabQL, the estimates are stored in a Q-table which contains an entry for every state-action pair \cite{suttonbarto2018reinforcement}. Each entry estimates the expected cumulative reward from taking that action in the given state and then acting optimally thereafter. The agent can then derive a policy by selecting actions with the highest estimated values. However, Sutton and Barto treat tabular methods as suitable when the state and action spaces are small enough to represent explicitly \cite{suttonbarto2018reinforcement}. TabQL may therefore provide a suitable baseline for tic-tac-toe, whereas Azul's much larger state-action space is likely to make storing and sufficiently exploring the table impractical.
