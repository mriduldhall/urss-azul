\section{Literature Review}
The literature review examines existing research on each game-playing AI approach to understand their general strengths and limitations. This evaluation helps to anticipate potential challenges before implementing the agents. The literature review then considers a more complex hybrid approach that demonstrates how different AI approaches can work together to build a potentially stronger agent. Finally, existing Azul implementations are reviewed to identify limitations in previous work and establish the research gap that this project intends to fill. 

\subsection{Minimax}
Yannakakis and Togelius' \emph{Artificial Intelligence and Games} describes Minimax as an algorithm for two-player adversarial games \cite{yannakakis2025artificial}. Minimax considers the possible moves available to each player in turn while assuming that both players play optimally. In a finite, deterministic, two-player, zero-sum game with perfect information, an optimal move can be found by exploring the entire game tree. However, searching the entire game tree quickly becomes infeasible as the complexity of the game increases due to the branching factor and search depth. \\

Shannon's \emph{Programming a Computer for Playing Chess} takes this idea further by considering the application of Minimax to chess \cite{shannonminimaxchess}. Since exploring the entire game tree is infeasible, Shannon proposes searching only a certain number of moves ahead and using an evaluation function to estimate the quality of the resulting game states. Shannon also considers selective search, which prioritises moves that appear more promising and hence reduces the game tree that needs to be explored. However, this comes with a risk of excluding an important alternative move. Knuth and Moore's \emph{An Analysis of Alpha-Beta Pruning} examines a further improvement that reduces the number of branches searched by excluding those that cannot influence the final Minimax decision \cite{knuthalphabeta}. However, the effectiveness of alpha-beta pruning relies on the order in which moves are considered. \\

Campbell, Hoane and Hsu's \emph{Deep Blue} demonstrates how search-based AI was developed into a chess-playing system capable of playing chess at world-championship level \cite{deepblue}. It defeated the reigning World Chess Champion Garry Kasparov in 1997. Deep Blue extended Minimax with alpha-beta pruning through parallel processing, a more complex evaluation function and a grandmaster game database. Although an equivalent database is less likely to be available for Azul, the other improvements may help address the inefficiencies of basic Minimax when developing an Azul agent. Collectively, these sources can therefore inform the implementation of Minimax as a search-based baseline for comparison with the other Azul agents. However, the implementation must also determine how to represent Azul's random factory replenishment since standard Minimax assumes deterministic transitions.


\subsection{Monte Carlo Tree Search}
Browne et al.'s \emph{A Survey of Monte Carlo Tree Search Methods} describes MCTS as an iterative algorithm that involves selection, expansion, simulation and backpropagation \cite{mctshistory}. Initially, a game state is selected from the existing game tree based on a tree policy. If the selected state has an unexplored move, then that move is added to the game tree, leading to expansion of the game tree. A game is simulated from the game state using either random or some policy-guided actions. The result of the simulated game is backpropagated through the game tree. This process is repeated many times in order to allow MCTS to estimate the most promising moves using the results of simulated games. Kocsis and Szepesvári's \emph{Bandit Based Monte-Carlo Planning} introduces Upper Confidence Bounds applied to Trees (UCT) as a tree policy for guiding MCTS \cite{mctsutc}. UCT works by balancing exploitation against exploration. Exploitation revisits previously visited promising states while exploration gives more attention to unvisited or less frequently visited states. \\

Browne et al. describe MCTS as an anytime algorithm since it can return a result whenever its computation is halted, although the reliability of its results generally improves with additional computation time \cite{mctshistory}. Basic MCTS requires little domain-specific knowledge and can be effective in games where non-terminal states are difficult to evaluate, although incorporating additional knowledge can improve its performance. This is particularly relevant to Azul since constructing a reliable heuristic requires substantial Azul-specific domain knowledge. However, a large branching factor or computationally expensive game simulations restrict the number of simulations that can be completed within a fixed amount of time, reducing the coverage of the game tree and producing less reliable results. These sources can therefore inform the implementation of MCTS as the baseline for the simulation-based search approach. The implementation must determine how to represent Azul's random factory replenishment during simulations. 


\subsection{Reinforcement Learning}
Yannakakis and Togelius' \emph{Artificial Intelligence and Games} describes Reinforcement Learning (RL) as an approach where an agent learns by acting within an environment and receiving positive or negative rewards \cite{yannakakis2025artificial}. The agent attempts to learn a policy, which is a strategy for selecting actions that maximises the expected cumulative reward, by repeated interactions with the environment. Unlike Minimax and MCTS, RL generally requires a separate training period in which the agent explores actions and improves its policy. Much of the computational cost is hence incurred before play, potentially allowing actions to be selected quicker once training is complete. This section considers three RL approaches, namely Tabular Q-Learning, Deep Q-Networks and Proximal Policy Optimisation, before investigating self-play as a method of generating training experience in two-player games.

\subsubsection{Tabular Q-Learning}
Watkins and Dayan introduce Q-learning as an approach that incrementally updates estimates of the quality of taking each action from each state \cite{qlearning}. They prove that these estimates converge to the optimal action values under specific conditions such as repeatedly sampling every state-action pair and a discrete representation. Sutton and Barto's \emph{Reinforcement Learning: An Introduction} explains that in Tabular Q-Learning (TabQL), the estimates are stored in a Q-table which contains an entry for every state-action pair \cite{suttonbarto2018reinforcement}. Each entry estimates the expected cumulative reward from taking that action in the given state and then acting optimally thereafter. The agent can then derive a policy by selecting actions with the highest estimated values. However, Sutton and Barto treat tabular methods as suitable when the state and action spaces are small enough to represent explicitly \cite{suttonbarto2018reinforcement}. TabQL may therefore provide a suitable baseline for tic-tac-toe, whereas Azul's much larger state-action space is likely to make storing and sufficiently exploring the table impractical.

\subsubsection{Deep Q-Networks}
Building on the principles of Q-learning, Mnih et al.'s \emph{Human-level Control through Deep Reinforcement Learning} introduces Deep Q-Networks (DQN), which replace the explicit Q-table with a neural network that approximates the action-value function \cite{dqn}. This allows the agent to generalise between similar states rather than storing a separate value for every state-action pair, hence potentially making larger and higher-dimensional state spaces more manageable. However, the introduction of a neural network introduces additional computational and implementation demands, such as the selection of an appropriate state representation, network architecture and training parameters. \\

Furthermore, van Hasselt, Guez and Silver reveal that DQN substantially overestimates action values in some Atari games and that these inaccurate estimates can lead to reduction in game performance \cite{doubledqn}. This represents a potential risk to investigate when applying DQN to Azul. They introduce Double DQN as a way of reducing this overestimation. Later, in \emph{Rainbow: Combining Improvements in Deep Reinforcement Learning}, Hessel et al. combine Double DQN with five other extensions and report improvements in data efficiency and final performance \cite{dqnimprovements}. These extensions may inform later experimentation, although building an understandable DQN agent remains the initial priority.

\subsubsection{Proximal Policy Optimisation}
Proximal Policy Optimisation (PPO) provides an alternative RL approach to the value-based approaches seen in TabQL and DQN. Schulman et al. introduce PPO as a policy-gradient method that directly adjusts a policy rather than learning action values and deriving a policy from them \cite{ppo}. PPO alternates between collecting experience through interaction with the environment and performing updates using the collected data. Its clipped objective discourages excessively large changes to the policy during each update, with the intention of producing more reliable updates. Although Schulman et al. report promising results across Atari games and simulated robot tasks, the experiments do not establish suitability for board games or Azul specifically. Furthermore, in \emph{Implementation Matters in Deep Policy Gradients: A Case Study on PPO and TRPO}, Engstrom et al. demonstrate that secondary code-level choices can substantially affect PPO's behaviour and performance \cite{ppoweakness}. Therefore, PPO's conceptual simplicity does not remove the need for careful implementation, configuration and repeated evaluation. Additional experimentation would be required before deciding whether PPO is a practical approach for the complete two-player Azul environment.

\subsubsection{Self-Play}
Self-play is a training approach to create training experience for RL agents for two-player and multiplayer  games. Tesauro's \emph{Practical Issues In Temporal Difference Learning} demonstrates its use through TD-Gammon, which generated training experience by playing games against itself instead of relying on a dataset of human play \cite{selfplay}. However, repeated training against a narrow set of opponents can limit the strategies an agent encounters. Lanctot et al. find that RL agents can overfit to the policies used during training and fail to generalise against other opponents \cite{selfplaydiversity}. They propose training against mixtures of policies rather than only the latest opponent by maintaining a diverse population of agents. Balduzzi et al. identify an additional risk in non-transitive games, where strategies can form cycles in which one policy defeats a second, the second defeats a third, and the third defeats the first \cite{selfplaycycle}. Although it is not yet known whether Azul exhibits non-transitive strategic relationships, this is something that should be considered during implementation. Opponent diversity, historical policies and evaluation against agents excluded from training should therefore be considered when designing the self-play procedure.


\subsection{Hybrid Approaches}
Although search-based and learning-based agents have been considered individually, they can also be combined so that each approach supports the other. Learned models can guide search towards promising moves and estimate values of game states. Silver et al.'s \emph{Mastering the Game of Go without Human Knowledge} demonstrates this through AlphaGo Zero \cite{alphagozero}. The system uses a neural network with policy outputs that identify promising moves and a value output that evaluates board positions. This network is trained using games generated through self-play and is incorporated into MCTS, where it guides the exploration and evaluation of the search tree rather than relying on randomly simulated games. This combination demonstrates the potential for learning and search to produce a stronger system together. However, it combines the training costs of a learned model with the decision time costs of MCTS and introduces additional implementation complexity. Furthermore, AlphaGo Zero's success in Go does not establish that the same architecture would be effective for Azul. A hybrid approach therefore represents a possible direction for future advanced implementation.


\subsection{Existing Implementations}
Existing Azul implementations must first be distinguished by their ruleset and number of supported players. Changing these configurations affects the available actions and interactions between players, which can lead to substantially different strategies. Directly comparing results obtained under different configurations may be misleading. Gendre and Kaneko's \emph{Ceramic} implements MCTS-based agents, demonstrating that such approaches are feasible in an Azul-derived environment \cite{ceramic}. However, because \emph{Ceramic} uses modified rules, its results cannot provide direct evidence of how MCTS would perform in the complete official two-player game. \\

Počatko compares Minimax and MCTS agents within an implementation of the official two-player game and reports that MCTS was the strongest approach under the tested configurations and computational budgets \cite{pocatko2021azul}. This provides evidence specific to Azul that can inform expectations for the comparison between the project's Minimax and MCTS agents. It also offers an external reference point when interpreting the later comparison between RL and search-based approaches. However, numerical results should not be used directly in results comparison because differences in implementation choices and resource budgets may substantially affect performance. \\

In \emph{Implementing Superhuman AI for Azul with a Variation of NNUE}, Rzepecki implemented both MCTS and Minimax-based agents for the official two-player game and reported that Minimax performed much better than MCTS \cite{rzepecki2025azul}. This contrasts with Počatko, who found MCTS to be the strongest approach under his tested configurations and computational budgets \cite{pocatko2021azul}. The contradiction reinforces that the relative performance of these approaches depends on implementation choices, heuristics and resource budgets, so neither result should be treated as a universal baseline. Rzepecki later developed the Minimax agent further by combining alpha-beta pruning with an efficiently updatable neural network (NNUE) evaluation function. Since this system combines learned evaluation with several search enhancements, it is not directly comparable with the approaches considered in this project. Nevertheless, it demonstrates the potential of hybrid learning-guided search and provides a useful reference for the playing strength such systems can achieve. Unfortunately, it cannot establish whether standalone RL approaches should perform better or worse. Sádovský instead implements DQN and PPO agents in an environment based on standard Azul rules \cite{sadovsky2025azul}. PPO performs substantially better than DQN, while DQN remained comparable with random play. Additionally, neither agent consistently defeated the heuristic opponent. However, these findings depend on the particular representations, network architectures, reward functions and training procedures used, so they do not establish that PPO will generally outperform DQN in Azul. \\

One public repository, \emph{AI-agent-Azul-Game-Competition}, implements MCTS, DQN and Minimax agents within a shared environment \cite{kaiyooazulcompetition}. However, its public summary presents individual demonstrations rather than a formal, controlled three-way evaluation using repeated trials and clearly reported computational budgets. Many other public Azul repositories also implement search-based or learning-based agents \cite{mgsweetazulmcts, domwilsonazul, azulai, azulrl}. Although these repositories provide useful evidence of implementation feasibility, they frequently lack formal evaluation results, documented game-rule validation tests or sufficient information of game rules to verify they match official two-player Azul rules. The gap addressed by this project is therefore the absence of a systematic and reproducible comparison of Minimax, MCTS and RL within a verified common environment. Furthermore, the reviewed implementations do not evaluate comparable approaches across another game. By also applying comparable agents to tic-tac-toe, this project investigates how their performance changes between a traditional, relatively simple game and a more complex modern board game, as well as how much of each approach can be shared between the environments.
